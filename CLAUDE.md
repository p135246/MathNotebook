# MathNotebook paclet

Paclet for writing math papers in Wolfram notebooks: referencing palette, LaTeX journal stylesheets, LaTeX ↔ notebook conversion, MaTeX integration.

## Layout

- `MathNotebook/` — paclet root: `PacletInfo.wl`, `Kernel/` (Package[] format, loader `MathNotebookLoader.wl`, usage strings in `Usage.wl`), `FrontEnd/Palettes/`, `FrontEnd/StyleSheets/MathNotebook/`, `Assets/`, `Tests/*.wlt`.
- `Scripts/Build*.wls` — generate ALL `.nb` artifacts (stylesheets, palette, tutorial). Never edit generated `.nb` files directly; edit the script and regenerate.
- `Notebooks/` — `Referencing.nb`, `Infrageometry.nb`, `TikZ.nb`, the original prototypes, kept as reference; do not modify.
- `LaTeX/` — the four sample papers, sources and PDFs, linked from the README. `Images/Palette.png` likewise. Neither moves: the README and the build scripts reference both by path.
- `Resources/` — incoming material: the two specimen papers `Tests/Specimens.wlt` measures, and anything downloaded. **Gitignored except its `.gitkeep`**, so nothing here enters history — neither paper is the paclet's to redistribute, and `PublishPaclet.wls` stages `Tests/`. The directory itself is tracked so a fresh clone has it.
- `Work/` — execution state, one file per item, status is the folder. `.claude/` and `.serena/` are tool state and stay ignored.

The root holds only `.gitignore`, `CLAUDE.md`, `LICENSE`, `README.md` and `run_tests.wls` beside those directories. There is no `Wiki/` and deliberately so — durable knowledge is this file, with `Work/` items holding the per-effort record (`RepoOrganization` T1, 2026-07-27).

## Conventions

- Conversion functions have pure cores operating on `Notebook` expressions (headless-testable) with thin `NotebookGet`/`NotebookPut` wrappers.
- In the `Package[]` format an **undeclared symbol is private to its own file** (`WolframInstitute`MathNotebook`<File>`PackagePrivate`x`). Calling such a helper from another file creates a distinct, definition-less symbol, so the call just stays unevaluated — **no message, no failure, the operation silently does nothing**. Every cross-file helper needs `PackageScope["name"]` in the file that defines it.
- All five template stylesheets are generated from the same base cell list as `LaTeXBase.nb` and each chains to `Default.nb`; they must define identical style names (enforced by `Tests/StyleSheets.wlt`).
- **`ComplexSystems` is the fifth template and the one that breaks the shared-counter clause, deliberately.** The other four declare one `Theorem` counter for all twelve environments, reset by `Section` and printed `Section.Theorem`; this one declares **one counter per environment with no section prefix and no reset**, because that is what the journal prints — the tell in the journal's own `ComplexSystems.nb` is that `Lemma` is declared standalone with `CounterIncrements -> "Lemma"` while fifteen siblings inherit `TheoremLike`. So `Tests/StyleSheets.wlt` counts **twelve** cells incrementing `"Theorem"` in each of the four and exactly **one** here, and asserts `Section` does *not* carry `{"Theorem", 0}`. It is also the only template whose numbers were measured from a journal's own artifacts rather than chosen: a 432 × 648 page carrying a 306 pt column (63 pt each side, which is the `.sty`'s `\textwidth=25.5pc`), display math flush left at a 2 pc indent rather than centred, `"PrintingMargins" -> {{0, 0}, {54, 54}}` so the column is positioned entirely by per-style `CellMargins`. Its two faces are commercial, so it is also the only sheet with a **screen/print font split** — Times/Helvetica bare, Sabon LT Std/Univers LT Std in the `"Printout"` variant, which is the journal's own answer. Neither the `.sty` nor the `.nb` carries a licence grant, so neither is vendored; `Resources/` holds them, gitignored, and `LaTeX/Sample-ComplexSystems.pdf` is a **notebook printout rather than pdfTeX output** — the one sample in that directory that is, because there is no redistributable class to compile against. Two further things about it. The **palette's stylesheet menu is a list of its own** (`$styleSheets` in `BuildPalette.wls`), not a scan of the shipped sheets, so this template was generated, measured, tested and unreachable from the paclet's own UI for a commit; `Tests/Palette.wlt` now derives the expected menu from the stylesheet directory minus `LaTeXBase`. And the **importer can never route to it**: a Complex Systems paper is `\documentclass{article}` + `\usepackage{amssymb,ComplexSystems}` — the journal's own sample is — while `documentStyleSheet` reads the class alone, so such a paper lands on `PlainArticle`.
- **A duplicated option in one `StyleData` cell resolves to its *first* occurrence** — measured for both a `FontSize` (33 over 77) and a `CounterIncrements` (`"Alpha"` over `"Beta"`). That is what makes every template override in `BuildStyleSheets.wls` a **prepend** rather than a rewrite: `mergeCell` puts the override ahead of the base options and the base copy is simply never reached, which is why a spec can carry a counter as safely as a font. Distinct from the neighbouring rule that of two `StyleData` *cells* for one name the first wins and the second is discarded whole — same direction, different granularity, and both silent.
- **A `CellDingbat` is inherited into the `"Printout"` variant, but the variant's `FontFamily` cannot reach inside it.** The dingbat is a `Cell` carrying its own font options, so a print font written on the style leaves the label in the *screen* face: measured, `ComplexSystems` set every "Definition 1." in Helvetica-Bold while the body around it printed in the print face. The whole dingbat has to be restated in the variant, counter and all. The label is not missing in such a PDF, it is merely in the wrong typeface — so this is invisible to every structural test and shows only in the embedded font list.
- **A `CellDingbat` wider than the cell's left margin is anchored at the window edge — clipped — with the body pushed right of the margin**, so "clipped label" and "entry hanging into the gutter" are one defect (`ImportDisplayDefects` T1, the causal paper's bibliography under `PlainArticle`). An imported entry's dingbat is its BibTeX key, and `[woodhous1973differentiable]` measures 173 pt at Palatino 13 but **190 at `PlainArticle`'s Source Sans Pro 15**, which is the widest of the six faces since that sheet's `Reference` began inheriting `Text` — so every sheet's `Reference` reserves a **205 pt** left margin (`BibliographyDisplay` T1; the same 15 pt of clearance the old 185 gave over 173), `PlainArticle` carrying the geometry *and the inheritance* across (the environments' clipping argument, `$plainGeometry` in the build script), and `ComplexSystems` deviating from its journal-measured 100/84 (→ 205/125) because those fit the journal's own numbered labels, not a key. Two subtleties: the style's `ParagraphIndent -24` is a hanging indent for a *hand-written* entry, and it moves a dingbat with the first line — so `referenceDingbat` writes `ParagraphIndent -> 0` beside every label it hangs, per-cell for the same reason an environment body's suppression is. And whether 185 clears the key depends on the face each sheet resolves, so `Tests/FrontEnd.wlt` measures the key at each sheet's own `Reference` font against its own margin (`ReferenceGutter`, asserting `100 < label < margin` — the lower bound because a `Rasterize` fault reads 0 and would pass a bare less-than). `Rasterize` here is 1 px = 1 pt, calibrated against `ImageSize`.
- **`PlainArticle.nb` is a fifth sheet and deliberately not a fifth template — it exists to declare *fewer* styles, so it is outside that invariant.** The four templates are journal typography; this one is `Default.nb`'s typography with the paper's *structure* added, and it is what `ImportLaTeXDocument` chooses when the `\documentclass` names no journal the repo has a template for (`amsart`/`amsbook`/`amsproc`, `revtex*`, `svjour*` are the only ones named; `article` included lands here). One rule decides its contents: a style Default has no notion of comes across from the base cell list whole (the twelve environments, `Proof`, `Caption`, `Date`, `Hyperlink`/`Citation`/`URL`), a style Default *does* declare contributes only the number or the word the document prints (the three sectioning levels and `Abstract`), and `Title`, `Text`, `Author` and the three `DisplayFormula` ones get nothing at all (`Reference` used to be among them and now carries its `CellMargins`/`ParagraphIndent` across, `$plainGeometry` — the dingbat-clearance bullet below). Every explicit `FontSize` is dropped and the `"Printout"` variants with it. Three things are not obvious. Without it an import lands on `Default.nb`, where a `\ref` to a definition renders **`2.0`** — the section counter increments and the theorem counter never does — and that is invisible to the kernel, to the round trip and even to the resolved counter values, so the assertion is a rendered PDF measured under *both* sheets. A child sheet's `CounterAssignments` **replaces** the parent's, so adding `{"Theorem", 0}` to `Section` means carrying Default's own eight resets across (T9's per-cell finding one level up). And `CellMargins` has to come across with the environments even though it looks like typography: a `CellDingbat` is drawn to the *left* of the cell margin, so "Theorem 1.1." at Default's 66 pt would be clipped.
- **A scan of `Default.nb` cannot answer "does this style exist".** It declares 54 names and neither `Hyperlink` nor `Link` is among them, yet both resolve — from front-end resources outside the file. Which styles `PlainArticle` defers to Default is therefore written out in `Scripts/BuildStyleSheets.wls` and pinned by `Tests/StyleSheets.wlt`, not computed.
- **`FrontEnd`FileName` is `HoldAll`.** `StyleDefinitions -> FrontEnd`FileName[{"MathNotebook"}, f[x] <> ".nb"]` stores *the unevaluated call* — together with the enclosing `Module`'s renamed local — and the front end then silently falls back to `Default.nb`. Substitute the name in with `With`. Every other use in the repo passes a literal string, which is why nothing hit this until T11.
- **`a -> b :> c` parses as `a -> (b :> c)`**: `Rule` and `RuleDelayed` have the same precedence and associate right. So a `Cases`/`FirstCase` rule whose *pattern* is itself an option needs that pattern parenthesised — `( StyleDefinitions -> … ) :> name` — or it matches nothing, silently, like the `~~`/`|` and `~~`/`:` traps below.
- Palette buttons must be cold-kernel-safe: `Needs["WolframInstitute`MathNotebook`"]` + fully qualified symbols, `Method -> "Queued"`.
- **The TeX importer has two halves with opposite failure modes, and `texToBoxes` needs both.** `ToExpression[tex, TeXForm, HoldComplete]` interprets the TeX as *one Wolfram expression*, so any fragment that is not one — `a, b`, `(V, E)`, `x_1, x_2`, `\begin{cases}…` — answers `$Failed` no matter how ordinary the mathematics is. `Convert`TeX`TeXToBoxes` (the box-producing half `ToExpression` itself calls first, autoloaded, no `Needs`) handles all of those correctly but is presentational: it renders `\mathcal{H}` as an italic `H` and `\ref{k}` as a `CounterBox` spelled out of the letters of "Section". So the expression path stays primary and the box path is its fallback (`presentationBoxes`), with `\ref`/`\eqref`/`\pageref` held at `$Failed`. Also: `ToExpression` answers `HoldComplete[$Failed]` on malformed TeX, which a bare `HoldComplete[expression_]` pattern matches — `MakeBoxes` then renders the literal word `$Failed` into the cell.
- **The box path cannot draw 179 of the 207 `\@unicode` macros in its own import table** (`$InstallationDirectory/SystemFiles/IncludeFiles/TeX/Import/*.tns`, `\varnothing` among them): any codepoint the front end's lookup lacks comes back as **`\[Null]` — U+F3A0, a *named* character drawn as nothing** — and inside a `RowBox` the character is dropped outright, so no pass over the boxes can restore the glyph. The repair is in the TeX instead: `glyphSentinelTeX` rewrites each such macro to a braced digit sentinel (braces so a script position keeps one token), `namedGlyphBoxes` maps sentinels back to drawable characters after conversion, and `texToBoxes` routes any fragment naming one straight to `presentationBoxes` — the expression path drops the glyph even when it parses. `$glyphlessMacros` pairs each macro with its glyph: the table's own intended codepoint where drawable, hand-chosen standard equivalents for the 47 whose intended codepoint is a legacy unnamed private-use slot (`leqslant` → E2FA became `\[LessSlantEqual]`). Two probe faults guarded the defect: `DownValues` is `HoldAll`, so `Length @ DownValues @ Symbol["…"]` reads 1 whether or not definitions exist; and in a UTF-8 kernel `ToString[char, InputForm]` prints a named character **raw**, so any named-character test needs `CharacterEncoding -> "PrintableASCII"` — without it a sweep reports every named private-use character as unnamed.
- **`\textbf`/`\textit`/`\emph` become styled runs, and the run's shape is dictated by what survives a save.** `fontSplit` runs **before** `splitInlineMath` because an argument may hold a math span whole (`\emph{pairing of degree $n$}` — hodgepaper has dozens), and the argument recurses through the whole inline pipeline, so nesting composes for free. A plain argument rides in the front end's native `StyleBox`; one holding math or a nested command has to be an inline `Cell[TextData[…]]` island — measured, a saved-and-reopened `StyleBox` with **list** content is split into one run per part with the math cell escaping the style *and dropping it* (the ButtonBox-splitting defect's sibling), while the Cell island returns byte-identical. `\textit` is told from `\emph` by the `"TextItalic"` style name, which also survives the reopen; a bare italic run — what the Format menu writes — exports as `\emph`, the semantic default. `fontTeX` rebuilds the command from the run rather than from stored source, so an edit to the styled text reaches the `.tex`; an empty argument (`\emph{}`) stays literal source, because neither shape survives a save empty. The reopen claim is pinned by `FrontEnd.wlt`'s `FontRuns` measurement beside the ButtonBox one.
- **The five TeX character escapes (`\&`, `\%`, `\_`, `\#`, `\$`) unescape into displayed text on import and re-escape on export, and a blanket inverse is impossible** — the importer deliberately leaves raw TeX in displayed text, and raw TeX is full of those characters: hodgepaper *displays* 49 bare `%`s (39 line-initial comment lines, 10 line-final continuations, 0 mid-line), a `#1` macro parameter inside a table its `%`-continuation glues to a Proof paragraph, and a failed `\begin{equation}` still carrying its `_`. So both directions scan a run with the **same segmentation** — `rawSegments` in `Document.wl`: complete `\begin`/`\end` spans matched with a back-reference (so a nested `\end{gathered}` cannot close a `\begin{equation}`), failed `$…$`/`$$…$$` spans still wearing their dollars, comment runs — and touch only the plain segments, so the two halves cannot disagree and every raw span goes back out verbatim. `unescapedRun` sits on the final prose runs of `inlineParts` (after every splitter has taken its pieces, so `ButtonData` keys and `SourceTeX` mirrors stay verbatim); `escapedRun` is applied by `escapedTextCell` *before* `referencesToTeX`, which turns buttons into command strings whose underscores are not prose. Three corners are decisions, each pinned by a test: a `#` adjacent to a digit is a macro parameter and is never touched in either direction; a `%` is a percent only strictly mid-line (line-initial and line-final are comments and continuations); and every rule list opens with **identity rules for the escaped forms**, so a missed unescape is never double-escaped and still round-trips byte-exact. `\$` is masked to a private-use sentinel before `splitInlineMath` reads its dollar as a math delimiter (T1's sentinel pattern), restored per segment — plain segments get `$`, raw spans get `\$` back, and one that rode into a converted island is restored in its `SourceTeX`. Finally, a `\ref` inside a *failed* span must stay in the span (`referenceSplit` protects `$`-pairs before splitting out buttons): turning it into a button strands the span's two dollars in separate runs, where the export escape reads each as a loose `\$`-dollar.
- **Binding a regex to a pattern variable renumbers its capture groups.** `span : RegularExpression[ "…(\\1)…" ]` wraps the whole regex in a group of its own, so a numeric back-reference silently refers to the wrong group — `rawSegments`' environment alternative matched nothing, with no message, while the same regex stood alone correctly. Named groups (`(?P<name>…)` / `(?P=name)`) are immune, and are what `$rawTeXSpan` uses.
- **The document layer (`Document.wl`) round-trips a paper by recording whitespace, not by rules about blocking.** Every cell carries a `"Separator"` tagging rule holding the source whitespace that followed it, and the opening/body/closing indents of an environment are each recorded too, so `ExportLaTeXDocument` is a plain `StringJoin`. Riffling with `"\n\n"` instead was 7 diff lines on one specimen and 38 on the other. Two pattern traps in the same file: a string pattern will **not** take a back-reference to a named `Alternatives` (`name : (a|b) ~~ … ~~ name` answers `StringExpression::invld`, not a non-match), so emit one rule per environment name with the name written literally into both delimiters; and structural delimiters must be anchored to `StartOfLine`, or `%\begin{example}` is matched inside its own comment and a commented-out block becomes a live cell.
- **An environment spans cells, and what holds it together is a pair of strings.** The `\begin{…}` (with its indent, optional title and trailing source) rides on the **first** cell of the group in an `"EnvironmentOpen"` rule and the `\end{…}` (with the whitespace before it) on the **last** in `"EnvironmentClose"`, so the body can go through `splitPieces` — the same function the document body goes through — and get its display math lifted and its nested environments recursed into while the export stays a plain `StringJoin`. Nesting composes by concatenation: an outer opening is prepended to whatever the first cell already carries, an outer closing appended. Two consequences that are not obvious. The name, the number and the QED square all come from the **style**, so a body of *n* prose cells would be numbered *n* times — the first prose cell keeps them and the rest carry `CellDingbat -> None`, `CounterIncrements -> {}`, empty `CellFrameLabels`; this is the one place a per-cell option is the *sheet-independent* choice, unlike the positive counter T11 rules out. And a `DisplayFormula`'s `CellTags` is a **mirror** of the `\label` inside its stored source, not the origin of one, so `cellTrailing` must not write it back — the moment such a cell is first in a body and carries the `\begin`, the label is emitted twice.
- **That block is held together by the *style*, and a `CellGroupData` carries no typography at all** — which is why the author-side control repeats the style rather than grouping cells. Measured: writing four cells as a group leaves every resolved `CellMargins` identical, `{130, 66, 130, 66}` grouped and ungrouped, so the reported "prose typed after a display equation falls out of the definition" is a margin and not a missing bracket. An environment body sits at **130** pt under six of the seven sheets against `Text`'s **66** (`ComplexSystems` 67 against 54, its `DisplayFormula` at 90), and that 64 pt is room for a label hanging to the **left** of the cell margin — "Definition 1.1." rasterizes at **79** pt at Palatino 13, so the body's indent cannot simply be lowered to `Text`'s without the documented dingbat clipping. So `InsertEnvironment[nb, Automatic]` continues a block by repeating its style with `CellDingbat -> None` and `CounterIncrements -> { }`, which is exactly what the importer already writes, and per-cell rather than as a declared continuation style for the importer's own reason: "this cell continues the one above" is true under every stylesheet, so a sheet swap still retargets the paper. Three things about it. The walk up from the selection (`enclosingEnvironment`) is a **`TakeWhile`** over the styles a body may contain (`$bodyStyles`: display math and the item family) and **not** a `FirstCase` — a `Text` cell above means the block ended there, and reaching past it continues the wrong block. Two options **travel** to whichever cell is now last, neither optional: `Proof` is the one environment whose style carries a `CellFrameLabels`, so the cell the block used to end on must suppress the QED square explicitly or it prints mid-proof; and an imported block's `\end{…}` rides on its last cell, where leaving it exports the author's new prose *after* the environment closed, as bare text, silently, with the notebook looking perfectly right. And the wrapper had to become `InsertEnvironment[style : _String | Automatic]` — left at `_String` the one-argument call stays unevaluated with **no message**, the exact shape `withInputNotebook` exists to close.
- **A hand-written block exports by acquiring those same two rules, which is why it needs no export clause of its own.** `cellToLaTeX` is keyed on `"EnvironmentOpen"`/`"EnvironmentClose"` and on nothing else, so `Cell["A graph is a pair", "Definition"]` exported as bare prose — measured, no `\begin{definition}` anywhere in the output — and all twelve palette environment buttons were therefore **screen-only**. `environmentWrapped` writes the rules onto a typed run instead of adding a clause, so separators, labels and nesting apply unchanged and one path serves an imported block and a typed one; it runs **after** the `Select`, or the `Output` cell a figure leaves behind splits a block in two. `environmentRuns` opens a run at a cell of an environment style carrying neither rule and no `CellDingbat -> None` (the census's own `Headed` key), extends it through continuations of the same style and through `$bodyStyles`, and **ends it at the last cell of the environment style** — a trailing equation stays outside, being as likely to follow the block as to belong to it. The environment **name** comes off `theoremDeclarations` and **not** off `theoremEnvironments`, which is that table joined *onto* the twelve defaults: the inverse lookup there answered `definition` for a paper whose only declaration is `\newtheorem{defn}{Definition}` — the one answer that cannot compile, since the document defines `defn` and nothing else. Two limits worth knowing before trusting a green suite. `Document.wlt`'s imported-continuation test asserts the tagging **shape** and survives dropping the `\end` move entirely, so that half is covered only by `Tests/FrontEnd.wlt`. And a hand-written notebook still exports a body with **no preamble**, so the `\begin{definition}` this produces has no `\newtheorem` to resolve against: the block is now correct and the file is still a fragment (`Work/Backlog/HandWrittenPreamble.md`).
- **A notebook that was never imported now gets a preamble written for it, and the layer that happens at is the whole of the design** (`HandWrittenPreamble`). `notebookToLaTeX` stays the **body** converter reading the stored frame and nothing else — every one of `Document.wlt`'s hand-written-block assertions is a bare `Notebook` with no tagging, so generating there prepends a document to all 113 of them — and `notebookToLaTeXDocument` one layer up is what `ExportLaTeXDocument` calls. **The discriminator is the *presence* of the stored `"Preamble"` key, never its value**: an imported *fragment* legitimately stores `""` (`documentParts` falls back to `{ "", source, "" }` with no `\begin{document}`) and round-trips byte-exact, so guarding on the value hands it a `\documentclass` it never had — which is why `storedDocumentTagging` is factored out of `documentTagging`, whose `Join` supplies all three defaults and destroys the distinction. Pavel's four calls, 2026-07-30: `article` always with the sheet named in a `%` comment; one `\newtheorem` per environment style **actually present**, first-appearance order, numbered as the sheet draws it (first takes `[section]` and the rest share its counter for six sheets, bare per-environment for `ComplexSystems`, which would otherwise disagree with the compiled paper invisibly); `amsmath`/`amssymb`/`amsthm` always with `graphicx`/`enumitem`/`hyperref` on a scan; `thebibliography` in place with no `\bibliographystyle`. Two findings inside it. **A `\title` alone prints nothing** — `article` needs `\maketitle`, which cannot go in the preamble — so it rides in the `"Separator"` of the last front-matter cell, the same carried-source slot the importer drops a source `\maketitle` into, and its *position* needs an assertion of its own since a count cannot tell before-the-author from after. And the generated preamble is **re-parseable by the importer**, its `\newtheorem` names being exactly what `environmentSourceName` produces for the same styles, so a re-import gives the same cells and re-exports byte for byte. Still open, and a different item: a hand-typed **list** has the pre-`EnvironmentBlocks`-T2 hole — an `Item` cell with no stored `EnvironmentOpen` exports as bare prose — which is why `enumitem` is scanned for and nothing typed can yet trigger it.
- **`Complement` sorts its result**, so "which cells are new" cannot be read with it: `Complement[ Cells[ nb ], before ]` answered the *Abstract* of a three-cell front-matter block and the cursor landed in the wrong cell, silently and on a real notebook. `Select[ Cells[ nb ], ! MemberQ[ before, # ] & ]` keeps document order. Read by difference rather than by counting the cells written, though — a `NotebookWrite` of a list is free to group.
- **The three sectioning commands and the three front-matter ones are one rule shape, and the style name lowercased is the command.** `commandRules` builds all six from `$commandStyles` and one `cellToLaTeX` clause writes all six back as `\<lowercase style>{content}`, so `Title`/`Author`/`Date` need no table of their own; a `Title` cell in a hand-written notebook therefore also exports as `\title{…}`. The braced argument must be matched **brace-balanced** (`$braceBody`, three levels) and not with `Shortest[…] ~~ "}"`: the specimen writes `\title{\vspace{-1.5cm}…}`, which the `Shortest` form cut off at `\vspace{-1.5cm`. A deeper nesting than the pattern allows does not match at all, and the command stays literal source. An `abstract` is a second `proof` — an environment outside the twelve that the sheets do declare a style for — so it lives in `theoremEnvironments` and `$plainEnvironments`, and the T7 body machinery then heads a multi-paragraph abstract once.
- **A paragraph that prints nothing produces no cell, and it is carried as *whitespace* — which is why it needs no export clause at all.** `\maketitle`, `\sloppy`, `\tableofcontents` and a comment-only paragraph become a `separatorMark` holding their own source verbatim (`carriedSourceQ` in `textPieces`), so they land in the preceding cell's `"Separator"` — a rule that already carries arbitrary source — and the export stays a plain `StringJoin`; a body-initial one lands in `"BodyPrefix"`. Only **content-free** commands may be listed: `\printbibliography` prints a bibliography and would be hidden along with it, which is why it is absent although the causal specimen carries one (commented out). Three things this turns on. A carried paragraph that *ends* an environment body would be the cell carrying the `\end{…}`, and does not lose it because `environmentPieces` takes the body between its first and last real `Cell` and folds every trailing mark into the closing delimiter — a body that is *nothing but* comments hits its empty-body branch and gets one cell carrying the whole environment. The test must be a **whole-paragraph** test, not a prefix test, or `\noindent Real prose.` vanishes. And "invisible" is only assertable on a **rendered page**: a cell count says a cell is gone, and the `FrontEnd.wlt` clause that used to assert `\maketitle` was on the page (1) now asserts it is not (0), which is the one measurement that nothing was drawn in its place.
- **Two carried shapes sit on a front-matter cell and they differ over who owns the rest of the argument** (`ImportDisplayDefects` T3, Pavel's R3 calls). A `"CommandPrefix"` is a leading run of layout commands with the cell still owning its text — that is what takes `\vspace{-1.5cm}` off the front of the specimen's title, and an edited title still reaches the `.tex`. A `"CommandTeX"` is the **whole** argument, carried because the cell displays something else: the `\author` block rides verbatim and the cell shows the names alone, so — the `.bib` asymmetry again — an author edited in the notebook does **not** reach the `.tex`. That negative is pinned by a test of its own, because it is a decision and not a bug. Three traps. Both are read by **one** `cellToLaTeX` clause (`Replace[ cellTagging[cell, "CommandTeX"], "" :> … ]`) rather than two clauses differing only by a `/;` condition — WL is free to order same-pattern definitions either way, so a conditioned twin is a coin flip. The prefix must contain at least one *command* and not merely whitespace, or every argument opening with a space acquires a tagging rule and every pinned cell changes. And `authorNames` takes its brace-group route only when the block is **nothing but** brace groups, else a `\thanks{…}` inside a bare name is read as the author.
- **The specimen census cannot see a display change that moves no counts** — measured as T3's second bite. Disabling the Author clause left `Tests/Specimens.wlt` fully green (the cell is still there, still styled `Author`, and the round trip is still byte-exact) while `Document.wlt` failed three; disabling the carried-paragraph pass moved 9 tests across three files, because that one *does* move counts. Same lesson as the nested-`\begin` bite, from the other side: a change to what a cell **contains** needs an assertion about its content, and the census is a detector for structure only.
- **A list is a T7 environment whose items are its cells, and the `\begin`, the `\item` and the `\end` all live in the *same* two slots.** Each wrapper is **prepended** to whatever `"EnvironmentOpen"` the cell already carries, so a nested list comes back in source order — outer `\item`, inner `\begin`, inner `\item` — with no new machinery and no new export clause, because the inner wrappers are applied first. `description` needs no case of its own: every one of its items carries the `[label]` that becomes its dingbat, which is what an `\item[(E)]` inside an `enumerate` wants too, and that dingbat is a **mirror** of the stored marker rather than the origin of one. Two things the front end gets wrong unless the cell says so, and neither is visible in the kernel or in a round trip: LaTeX restarts every list where `ItemNumbered` runs on until a `Section` resets it (so the first item carries `CounterAssignments`, else two lists in one section read 1, 2, 3, 4), and an `\item[label]` consumes no counter (so it carries `CounterIncrements -> {}`). Assert both by reading `CurrentValue[cell, {"CounterValue", …}]` off live cells — an item's dingbat is `1.`, which collides with everything in a PDF's plaintext.
- **The numbering is the document's, not the sheet's, and it is written on the cell that heads the environment.** A `\newtheorem` declares which counter an environment shares, which sectioning level resets that counter and is printed before it, and — the starred form — whether it is numbered at all; the sheets declare one `Theorem` counter for all twelve styles, reset by `Section` and printed `Section.Theorem`, so exactly **one** counter group can be left to them (the first declared numbered per section) and every other one deviates. This is not the per-cell counter T11 rules out: the numbering is declared in the preamble and the preamble is carried verbatim, so a sheet swap cannot change what the compiled paper prints and must not change what the notebook shows — the sheet owns typography, the preamble owns numbering. The **reset** goes on the first cell that *increments* the counter after each resetting cell, never on the resetting cell: a `Section` style declares three `CounterAssignments` of its own, the front end has no additive form, and a per-cell option would replace all three. An arbitrary counter name (`"TheoremDefn"`) needs no declaration anywhere, and a per-cell `CounterIncrements` **replaces** the style's rather than adding to it, which is what makes an independent counter possible at all. Two numbering facts that are not in the source: `amsart`/`amsbook`/`amsproc` number equations within the section and never say so (`\numberwithin` says so for any class), and an equation's number lives in `CellFrameLabels`, so that is where its section prefix goes. `\theoremstyle` is *not* read — it decides weight and slant, not the number.
- **`CounterFunction` on a `CounterBox` is real, front-end-evaluated, and almost nothing evaluates there.** It is how enumitem's `label=(\alph[star])` renders `(a)`, `(b)` where `ItemNumbered` renders `1.`, `2.` — the front end still owns the counting, so a `\ref` to the item still resolves. But measured: `RomanNumeral` works and `Part` on a **literal** list works, while `FromCharacterCode`, `StringTake`, `ToLowerCase` and even ``FEPrivate`FromCharacterCode`` each render as their own unevaluated expression, in full, in the dingbat. So every format is a literal table indexed by the counter, built by letting `With` substitute the table into `Function`'s held body.
- **A cross-reference has to read its chain off the target cell, not off the target's style.** Once a definition can be numbered per subsection its dingbat holds three `CounterBox`es where `$referenceLabelSpec` says two, so `\ref` copies the boxes out of the target's `CellDingbat` (or, for a display formula, its `CellFrameLabels`) and inserts the tag at position 2; only a cell carrying no number of its own falls back to the style's spec.
- **`*)` inside a Wolfram comment closes it wherever it stands**, so a comment quoting `(\alph*)` or any other TeX star followed by a paren turns the rest of the file into a syntax error. Spell the star out in prose.
- **`StringCases` tries its rules in the order given at each position**, not longest-first — verified. The `\newtheorem{x}{X}[section]` rule must precede the bare `\newtheorem{x}{X}` one, or every declaration matches as bare and silently loses its level.
- **A depth walk over LaTeX source cannot be anchored to `StartOfLine`.** Counting only line-initial `\begin{`/`\end{` is asymmetric, and hodgepaper writes `\begin{cases}` inline with its `\end{cases}` at the start of a line: the depth went to −1 and items (b), (c), (d) of that list silently became *continuation paragraphs* of item (a). Count both delimiters wherever they stand and mask the comments instead — `uncommented` replaces each `%`-tail by spaces of its **own length**, so every position still indexes the same character and the slicing stays valid. `StartOfLine` still guards the structural rules; it just cannot guard a depth count. The loss was invisible to the byte round trip *and* to the structure census — only counting stored markers against the source's `\item`s caught it, which is why `Items`/`ItemsHeaded` are census keys.
- **T7's "the head goes on the body's first *prose* cell" is false for items.** All 102 environments of the two papers open with prose, but 6 of their 31 items are an `align` and nothing else, and those rendered with no bullet, no number and no `[label]` — for a `description` item the label is the whole content. `itemHead` writes the dingbat onto whatever cell opens such an item (free on a display formula: its number lives in `CellFrameLabels`) and **appends** to the counter the cell already increments. It is the one place a positive counter goes on a cell. Restyling the display cell as an `Item` costs its centering and its number; inserting an empty head cell injects a `"\n\n"`, because `cellSeparator` maps a recorded `""` to `"\n\n"`.
- **`Cases[ opts, FontSize -> _ ]` reads that `Rule` as a *transformation*, not a pattern, and silently answers `{}`.** Selecting options out of a list is the one place this bites constantly, because the thing you want to match *is* a rule: `Cases[ {CellMargins -> …, FontFamily -> "Times", FontSize -> 14}, FontSize -> _ ]` is `{}`, and so is the `Alternatives` form. The proof it is being read as a replacement rather than a pattern: `Cases[ {FontSize, FontFamily}, FontSize -> _ ]` answers **`{_}`** — it matched the bare *symbol* and returned the literal blank. Wrap the whole option in `HoldPattern` (`Cases[ opts, HoldPattern[ ( FontFamily | FontSize ) -> _ ] ]`), which is the only form that works; `_Rule` alone takes everything. Measured while reading `ComplexSystems.nb`'s style options, where it reported *every* style as carrying no font size at all — the same silent-empty failure as the `StringCases` and `Count[ list, s_ :> expr ]` traps.
- **The general rule behind that one: any pattern argument whose head has a value is evaluated before matching.** `Cases[ panel, DialogReturn[ tag_ ] :> tag, Infinity ]` answers `{ }` over a panel full of `DialogReturn`s, because `DialogReturn[ tag_ ]` is evaluated as an ordinary expression first — five assertions in `Referencing.wlt` were passing nothing until each was wrapped in `HoldPattern`. `Rule` is only the case that bites most often, being what an option *is*; the trap is the head, not the `Rule`. Its mirror is the next bullet, where an expression that should evaluate does not.
- **`ReplaceAll` inserts its right-hand side *unevaluated*, so a blanket string rule over a notebook lands as a literal call inside any held box.** A reference page's `PrimaryExamplesSection` is an `InterpretationBox`, which is `HoldAllComplete`: `page /. s_String :> StringReplace[ s, old -> new ]` therefore wrote `StringReplace["Basic", { … }]` into the page as *content*, nested twice where two passes ran, and the file still parsed and still exported. Renaming a symbol across a `.nb` is **text** surgery on the file, not expression surgery; targeted rules on cells outside any held box (`Cell[ _, "Notes", ___ ]`) are safe, and inserting plain strings rather than calls is safe anywhere.
- **`StringCases[s, patt :> ""]` returns `{}`, not `{""}`** — a match whose replacement is the empty string is dropped from the result, so a probe cannot tell "the pattern did not match" from "it matched and the capture was empty". Give the rule a non-empty RHS (a list, a `Cell`) to test such a pattern at all. Distinct from, and as silent as, the `First @ StringCases[…, default]` trap below.
- **In a string pattern `|` binds tighter than `~~`**, so `A | "{" ~~ B ~~ "}"` is `StringExpression[Alternatives[A, "{"], B, "}"]` and a brace-group alternative needs its own parentheses — without them the pattern matches nothing, silently. The complement of the `~~`/`:` note below.
- **`StringSplit[""]` is `{}`, not `{""}`** — so `inlineContent`/`referenceContent` turned an empty environment body into `TextData[{}]`, which no exporter reads back as text and which therefore printed the literal `Cell[…]` expression into the `.tex`.
- **An imported `\ref` is a bare `CounterBox` chain, not `citationButton`.** LaTeX authors write the word themselves (`Theorem~\ref{Thm:2}`), so the palette's prefix would say it twice; `\eqref` is the same chain in parentheses, and which command it was is recovered on export from whether the box is parenthesised. Numbering only works under a MathNotebook stylesheet — the counter lives in `CounterIncrements` on the style — so on `Default.nb` a definition reference renders `2.0`, which looks like a broken reference and is not one. Any front-end test of numbering must install the sheet.
- **A `.bib` bibliography's `Reference` cells emit nothing into the `.tex`.** The entries are not in the source — it says `\bibliography{refs}` — so the block's **last** cell carries those commands verbatim and every earlier one carries a `"Suppressed"` tagging rule that `notebookToLaTeX` filters out. Two consequences: the `.bib` stays the source of truth, so editing an entry in the notebook does not reach the `.tex`; and no round trip can detect whether the bibliography renders at all, which is why the assertion lives in `Tests/FrontEnd.wlt`. A `\cite`, by contrast, converts **unconditionally** where T3's `\ref` needs a target cell — a citation's label is literal text (`referenceLabel`'s `[key]`, the same string the entry's dingbat shows) and is right with no bibliography, where a `CounterBox` would render `XXX`.
- **A compound `\cite{a, b}` is one Citation button per key, and the command's bytes live in `ButtonNote`.** The old single button's compound `ButtonData` resolved to no cell, so the click silently did nothing (`FirstReadingDefects` T3). Each member's `ButtonData` is its own trimmed key; the opener's note is `\cite[opt]{` up through its raw key and each continuation's is its comma plus raw key, so `recomposedCitations` rebuilds the one command byte for byte however the source spaced its keys — keyed on the **notes, never the separators**, because the literal `", "` between two members is indistinguishable from prose between two *separate* `\cite` commands, which must stay two. **Measured: `ButtonNote` survives a save exactly as `ButtonData` does** — the reopen-split copies every option onto every fragment — which is why `mergedButtons` keeps the first fragment's whole option sequence instead of restating two of them. Degradation is per member: an opener alone closes over its own key, an orphaned continuation falls to the per-button `\cite`, and a notebook saved before the split still exports its compound button byte-exact through `citationTeX`'s key count. Three edges. The `TextData` pass in `referencesToTeX` is a levelled `Replace`, not `ReplaceAll` — ReplaceAll never descends into what it replaced, so an island's own `TextData` (a citation inside `\emph{…}`) was reached by neither the merge nor the recomposition. A key list `StringSplit` does not reconstruct (a trailing comma's empty key) keeps the old single-button shape, trading the click for the round trip. And the per-key labels and display separators are **mirrors** of the note bytes, so a census of displayed prose must strip a `ButtonBox` to its label (`specimenProse`) or every recomposable citation counts as literal `\cite{` left in the text.
- **The other bibliography is the opposite case, and the two differ over who owns the entries.** A `thebibliography` written into the `.tex` *is* the source, so the notebook owns it and writes it back — an edited entry reaches the `.tex`, where an edited `.bib` entry does not. Mechanically it is T8's list one command down: `entryCells` is `listCells` with `itemChunks` pointed at `\bibitem` instead of `\item`, so the `\begin` rides on the first cell, each `\bibitem[label]{key}` in that cell's `"EnvironmentOpen"` slot, the `\end` on the last, and the export needs no new clause. Both routes show `referenceLabel`'s `[key]` as the dingbat so an entry and a `\cite` to it read alike — which is why a `\bibitem[Sm09]{key}`'s *printed* label is carried in the marker and not shown; showing it would make the two disagree. And a `Reference` cell's `CellTags` is a **mirror** of that key, not the origin of a `\label`: it joins `DisplayFormula` in `cellTrailing`'s exception, or every entry exports a `\label` the source never had.
- **Writing a bibliography the notebook did not import is the same two strings from the other side, and three parts of the block are *positional* while only one *travels*.** Positional: the `\begin{thebibliography}` prefix, which belongs to whichever entry is first; the `\end`, which belongs to whichever is last; and each recorded `"Separator"`, which describes a gap at a place in the source rather than anything about the entry before it. Travelling: the cell's own `\bibitem` marker, text, tag and dingbat. `InsertReference` has three cases told apart by what the block's last cell carries — no `Reference` cell at all gives the anchor plus a first entry carrying **both** delimiters; a `thebibliography` paper gets the entry appended with the `\end` **moved** onto it; a `.bib` paper's entry is suppressed and goes **before** the command-carrying cell, with `InsertReference::bibfile` saying it cannot reach the `.tex` — and `SortBibliography` reorders under the same split, pinning that carrier last. Three things are not obvious. The first entry's opening and its own `\bibitem` are **one string**, `environmentOpened` having composed them, so they are separable only at the **last** `\bibitem` in it. **Counting the delimiters cannot detect a wrong split and neither can the round trip**: leaving the opening to travel on its own cell still yields exactly one `\begin` and one `\end`, both at the end of the list, so an assertion has to read the delimiters off the reordered cells or compare their *positions* in the source. And positions are taken with `Position` at any depth, never over `notebookCellList` — that flattens, and putting a flattened list back discards every `CellGroupData`, un-collapsing the whole paper on each insert.
- **The bibliography anchor is a `Section` cell reading `References` and each of its three options is load-bearing.** `CounterIncrements -> { }` because `thebibliography` prints an **unnumbered** heading, and a plain `Section` reads "6 References" in the notebook where the compiled paper has no number there; a `"Suppressed"` tagging rule because that environment prints the heading **itself**, so a cell emitting one too puts it in the PDF twice; and `CellTags -> $bibliographyAnchorTag`, which is how the sort finds where the block begins. That last one is a marker and not a citation target, so `citationChoices` drops it — measured on the installed paclet, where the chooser offered `MathNotebookBibliography` beside the real keys.
- **A declared `.bib` that is not on disk is invisible to every detector this repo has** — the paper simply comes back with no `Reference` cells, the round trip is exact either way, and no census key counts a bibliography that is not there. `ImportLaTeXDocument::nobib` reports it, once per declared file (`DeleteDuplicates`: a paper names its `.bib` in the preamble and again where the list is printed). hodgepaper is the live case, declaring `\jobname.bib` and shipping without it.
- **`LaTeX/Sample-*.tex` are the only documents the repo actually contains, and the only ones anywhere here with a `thebibliography`** — both specimen papers use a `.bib`. They are small and cover the whole converter, so `Tests/Specimens.wlt` pins them beside the two absent papers and a fresh clone still asserts something.
- **A `.bib` field cannot be found by a string pattern**: a value holds both the comma that separates fields and the braces that end the entry (`title={A first paper, with a comma}`). `Accumulate` over the brace characters gives the depths in one pass — cut at the commas at depth 0, stop where the depth first reaches −1. Also, six named characters such a parser wants do not exist (`\[NAcute]`, `\[SAcute]`, `\[ZAcute]`, `\[IBar]`, `\[OBar]`, `\[UBar]` print as their own literal name) while their neighbours do; sweep an accent table in the kernel rather than inferring it.
- **A `figure` is the caption plus the code that draws the picture.** The caption becomes a `Caption` cell the notebook owns and writes back, and the rest of the environment's source — `[htpb]`, `\centering`, the `\includegraphics` options, a whole `tikzpicture` — rides verbatim in a `"FigurePrefix"` rule with everything after the caption in `"Trailing"`, where `labelledCell` finds the `\label` as it does for a section. That is how TikZ survives a round trip the notebook cannot render. Each `\includegraphics` becomes an `Input` cell holding `Import[FileNameJoin[{NotebookDirectory[], file}]]`, to be replaced with the code that *generates* the picture; the whole evaluation family (`Input`, `Output`, `Code`, `Print`, `Message`, `Echo`) emits nothing into the `.tex`, so a live figure cannot leak into the source — and equally, the generating code never reaches it. A captionless figure owns nothing and re-emits from `"FigureTeX"`. Figures number from the `Caption` counter straight through the document, as `article` does.
- **`ExportLaTeXDocument` writes one file, and a `.tex` alone is not a submission — `ExportLaTeXBundle` writes the directory.** Measured on the second specimen — `main.tex`, seven PNGs, `references.bib` — an export into an empty directory leaves `main.tex` alone in it while that same `.tex` names all seven `\includegraphics` files and `\bibliography{references}`: the round trip is byte-exact and the result compiles nowhere but the paper's original directory. Note the asymmetry with the journals: arXiv wants a source tree and *Complex Systems* wants none, being notebook-native with a Wolfram Cloud form. Five things about the bundle that are not obvious.
  - **The plan is a pure function of the source text, and that is what makes it testable.** `bundlePlan[source, home, jobName]` pairs every name the source uses with where it is on disk, so what a bundle *would* contain is assertable without writing one; the write is asserted separately, because a plan that is right and a directory that is empty look identical from the plan's side. The names come off the exported `.tex`, not off the notebook's cells — the `Input` cell holding `Import[FileNameJoin[{NotebookDirectory[], f}]]` is a *mirror* of the stored `\includegraphics`, and reading the source is the one route that also covers a `.bib` and a `tikzpicture`'s `\includegraphics`.
  - **The `.bbl` is compiled in a scratch copy, and that is not fussiness.** arXiv runs LaTeX but **not** BibTeX, so a `\bibliography` paper compiles there only if the `.bbl` travels with it — copying every `.bib` is necessary and not sufficient. arXiv also excludes `.aux`, `.log`, `.pdf` and `.ps`, and a run leaves all four beside the `.tex`; compiling in a copy of the bundle and bringing back only the `.bbl` satisfies both clauses with no cleanup pass. **No PDF ever goes in** — a compiled paper beside its source is a rejected submission, not a convenience. `\addbibresource` is biblatex and wants `biber`, not `bibtex`.
  - **A `thebibliography` paper declares no `.bib`, so no run is attempted for it** — the entries are already in the `.tex`. All four `LaTeX/Sample-*.tex` are that shape, so the samples bundle to a `.tex` alone and are *correct* doing it. hodgepaper is the opposite live case: it declares `\jobname.bib`, ships without it, and its bundle is short by exactly that file and says so.
  - **A named figure with no file is reported, never evaluated** (the T1 decision). The only way an `\includegraphics` reaches the exported source at all is from an imported paper's stored markup — the whole evaluation family emits nothing — so the case is an author who replaced the `Import` with generating code and whose shipped file has gone. Evaluating it would have to guess the format (arXiv accepts PDF/PNG/JPG for PDFLaTeX and EPS/PS for LaTeX and **converts neither**) and the size the source's own options assume.
  - **Two traps.** `Lookup[{}, "Target"]` reads the empty list as an empty *rule list* and answers `Missing["KeyAbsent", …]`, so a `Join` built from it stays unevaluated **inside the returned Association** — use `Map[#[key] &, …]` over a list of associations. And the bundle directory may be the paper's own (the palette's dialog allows it), which makes every copy a file onto itself: `CopyFile` refuses that with a message rather than treating it as a no-op, so compare resolved paths and skip. An exclusion test must be keyed on the **job name** and not on the extension — `plot.pdf` is a figure, and arXiv accepts PDF figures.
- **The front end normalizes displayed boxes and only displayed boxes, so a probe keyed on the normalized shape reads 0 the moment the box moves into a slot.** Measured either way in one front end (`EditableMaTeX` T1): a `GraphicsBox` written as a cell's content comes back with its options spliced up as its own arguments — `ImageSize` at position `{1,1,1,1,4}`, so `GraphicsBox[ ___, ImageSize -> { w_, _ }, ___ ]` reads 91.4887 — while the *same* graphic parked in a `TemplateBox`'s association slot comes back exactly as the kernel wrote it, options still in the nested list `ToBoxes` produced (`{1,1,1,1,1,Key["boxes"],2,1}`), where that pattern reads **0**. The width is present and identical in both. `Tests/FrontEnd.wlt`'s `maTeXWidth` was that pattern, so wrapping the MaTeX picture failed the ConversionUX T2 *size* test with `{28, False, False, True}` — a size regression reported where nothing about the image had changed. Read such an option **wherever it stands**, off the `GraphicsBox` found first.
- **A byte-identical round trip measured in one kernel does not survive a file.** Saving a notebook and opening it again splits a `ButtonBox[RowBox[…]]` inside a `TextData` into one button per run — this is not only `NotebookWrite` — so every imported citation and cross-reference came back multiplied: 14 buttons became 46 on the specimen, `\cite{a, b}` exported five `\cite` commands, and `\eqref{k}` came back as `\cite{k}\ref{k}\cite{k}` because the parentheses had been carried off into buttons of their own. `mergedButtons` in `Document.wl` rejoins consecutive buttons on one key before anything reads them. Any fidelity claim about a notebook must go through `Export`/`NotebookOpen`/`NotebookGet` at least once. The same reopen also **groups** cells into `CellGroupData` — harmless, since `notebookCellList` flattens, but a naive `Cases[…, Cell[_, style_String, ___]]` on a reopened notebook then reports almost nothing.
- **`NotebookEvaluate` inside `UsingFrontEnd` hangs**: the front end's evaluator is the kernel driving it. Put an `Output` cell in kernel-side with `ToBoxes` instead — cheaper, and the assertion is the same. (Relatedly, `Cases` on a `Notebook` defaults to level 1, where the only elements are the cell *list* and the options.)
- **In a string pattern `~~` binds loosest and `:` tightest**, so `optional : ( … ) | "" ~~ rest` is `StringExpression[Pattern[optional, Alternatives[…, ""]], rest]`, not an `Alternatives` over the whole pattern as it reads.
- **`First @ StringCases[s, rule, default]` is a silent bug** — the default lands inside `StringCases` as the match count, the call returns unevaluated, and a `Module` destructuring downstream leaves symbolic values with no message. Always `First[ StringCases[...], default ]`.
- **A TeX letter the kernel has a value for is a third failure mode of the expression path**, alongside "not one expression" and "malformed". `ToExpression["E", TeXForm]` is Euler's number and `"I"` is the imaginary unit, so `texToBoxes` returned `"\[ExponentialE]"` / `"\[ImaginaryI]"` — the wrong glyph, not a blank, and silently. Sweeping `a`–`z`, `A`–`Z`: those two and no others. Such a parse is treated as a misread and handed to `presentationBoxes`, which is right about all of them. Two traps: in a pattern `E | I` is `Alternatives[E, Complex[0, 1]]` — `I` evaluates, `E` does not — so it fixes `E` and silently misses `I`; both need `HoldPattern`. And `\[ExponentialE]` is U+F74D, a private-use character a terminal prints as nothing, so `Print`/`InputForm` report a wrong glyph as an empty one — read it with `ToCharacterCode`.
- **A subscripted letter that names a special function is a fourth failure mode of the expression path**, beside "not one expression", "malformed" and the `E`/`I` letters. `texToBoxes["K_k(G)"]` answers `TemplateBox[{"k","G"}, "BesselK"]` and `texToBoxes["T_k(G)"]` answers `ChebyshevT` — the *Bessel function* and the *Chebyshev polynomial*, for a paper whose `K_k(G)` is a set of cliques. It renders plausibly and means something else, so no display test and no round trip can see it: the boxes are a template the front end draws as `K_k(G)`, and the `.tex` comes back from the stored source either way. Same shape as `\[ExponentialE]`: a parse that is *wrong* rather than absent.
- **A named character prints as nothing, so a box read can invent a missing operator.** `ToString[ texToBoxes["G = (V, E)"], InputForm ]` shows `RowBox[{ StyleBox["G","TI"], "", RowBox[…] }]` — an apparently **empty string where the `=` should be**, which reads as a dropped operator and was reported as one. It is the private-use `\[LongEqual]`, and the render has the sign in it. The rule this repo already states for `\[ExponentialE]` generalises: read a suspicious box with `ToCharacterCode` or a `Rasterize`, never with `InputForm` in a UTF-8 terminal.
- **The front end sets its own spacing in typeset mathematics, and that — not the box structure — is why generated inline math looks loose.** `𝒦(G)` in an `InlineFormula` cell measures **107 px** at 216 dpi as a nested `RowBox[{ 𝒦, RowBox[{ "(", G, ")" }] }]`, **107** as a bare *string* `"𝒦(G)"`, **107** under `AutoSpacing -> False`, 97 flat and ungrouped, 112 in the shape the MarkdownToNotebook parser writes (`SpanMaxSize -> 1` parens, `"TI"` styling). A string measuring the same as a `RowBox` is the finding: the front end reads a letter followed by a parenthesised group as a **product** and sets a thin space, and a script glyph adds side bearing on top of it. So no box surgery removes the gap, and the built-in TeX assistant on `\mathcal{K}(G) = K_k(G)` draws `K (G) = K_k (G)` — losing the `\mathcal` too — where MaTeX draws it tight. **But MaTeX is a choice and not a default** (Pavel, 2026-08-01): native typeset boxes are what a notebook holds and what a machine with no LaTeX can open; MaTeX is what the author converts a selection *to*, from the palette.
- **A converted cell can become several cells.** Display math is normally written glued into a paragraph — `\begin{equation*}` on the line after the prose, no blank line anywhere — and it has to be lifted into its own `DisplayFormula` cell, so `convertLaTeXCell` may answer with a list and `mapCells` flattens. One delimiter table (`$displayDelimiters`) generates both the anchored whole-cell rules (`displayParse`) and the unanchored split rules (`splitDisplayMath`), so the two halves cannot disagree about which environments exist; `Shortest` in the unanchored rules is what stops two environments in one paragraph matching as a single span. The consequence for any round trip: the pieces are source-verbatim but the paragraph blocking is not, and the join that restores it is a single `"\n"`, not `"\n\n"`.
- **An equation number is invisible to a single-cell `Rasterize`.** `DisplayFormula` and `DisplayFormulaNumbered` on the same body measure identical ink (243 for `x^2+y^2=z^2`), because the number is a `CounterBox` — the same reason a tagged counter reads `XXX`. Rendering the whole notebook separates them (1268 unnumbered against 1368 numbered), which is the only way to assert "unnumbered" as a display fact rather than as a style name. What actually separates the two methods is the **canvas, not the method**: `inkOf` counts every pixel that is not white, so the appearance has to be pinned, and it takes **both** options — `Background -> White` *and* `LightDark -> "Light"`, which is what `inkArea` does and what `notebookInk` did not. Neither alone is safe, and the two fail in opposite directions. With **neither**, a dark appearance counts the whole page as ink. With the **background alone**, the paper is white and the prose is still drawn in the dark appearance's light foreground, so it is white on white and a `Text` cell measures exactly **0** — every comparison against it inverts, silently, and `Tests/FrontEnd.wlt` sat red on precisely that for a session and a half (`ConversionUX` T2 found it, not the item that wrote the test). Pinned both ways the numbers are stable and are the ones this file quotes: one `Text` cell **2440**, the two formulas 1268 and 1368. (`Background` does reach the exported PNG — `LightBlue` gives a `{222, 240, 255}` corner.) A measured **0** deserves an assertion of its own rather than a place in a comparison. `WindowSize` is not a lever and need not be pinned: the export crops to the content, so the width follows the text (101, 516 and 116 px in one run) and ink is wrap-invariant.
- **`FirstCase` with no default is a silent pass in an ink test.** `inkArea @ FirstCase[ notebook, Cell[ _, "DisplayFormula", ___ ] ] > 0` asserts nothing about whether the cell exists: `Rasterize` **draws** the returned `Missing["NotFound"]`, which carries 653 ink. `Tests/FrontEnd.wlt`'s "the formula renders" clause was passing under a converter that produced no `DisplayFormula` cell at all; it now maps an absent cell to 0.
- **A byte-identical round trip cannot detect a converter regression either, so `Tests/Specimens.wlt` pins a structure census beside it.** Dropping `figureRules[]` from `structureRules` leaves both specimen papers exporting their source byte for byte — the figure markup is carried verbatim either way — while the census fails three tests and names what went: cells and styles, tags and counters, and the `\includegraphics` that came back into the prose. The reverse bite, forcing `cellSeparator` to `"\n\n"`, fails only the round trips. Neither detector subsumes the other; a fidelity claim alone is not a correctness claim. A third bite showed the census does not subsume everything either: making a nested `\begin` overwrite the inner one instead of composing with it left both papers byte-identical *and* every census number intact, because neither opens an environment body with a nested environment — only the synthetic case in `Document.wlt` caught it. The census's `Environments`/`Headed` pair is the T7 invariant that replaced "one environment is one cell": exactly one cell per group is headed, and a body headed twice or not at all is invisible to both the round trip and the style counts. `Headed` keys on the **absence of `CellDingbat -> None`** and not on a positive counter — T9's starred environments legitimately carry `CounterIncrements -> {}`, and under the old key they read 67 of hodgepaper's 71 and looked exactly like a T7 regression. A fifth bite: dropping T9's whole counter-reset pass leaves both papers byte-identical *and* every other census number intact, because a `CounterAssignments` is read by no exporter and counted by nothing else — hence the `Numbering` keys, `Resets` among them.
- **Round-trip fidelity cannot detect a display defect.** The exporters read the stored `"SourceTeX"` tagging rule, not the boxes, so a cell that renders as a blank still round-trips byte-identically. Display has to be asserted separately; rasterized **ink area** works headless and is well separated (`Blank < Converted < Literal` measured 390 / 575 / 703 for an inline `$(V, E)$`, the middle one having lost the two `$` glyphs).
- **`InputNotebook[]` answers `$Failed` when no document is open — an ordinary UI state, and a silent no-op in five entry points until `withInputNotebook` (`BasicFunctionality` T2).** `CopyCellReference` and `TagSelectedCell` guarded `SelectedCells[ InputNotebook[] ]` with `{ cell_, ___ }` and `{ } :> MessageDialog["Select a cell!"]`, but `SelectedCells[$Failed]` stays **unevaluated** and so matches neither: the `Replace` fell through and returned its own argument, so with a palette open and no paper beside it all five returned an unevaluated expression with **zero messages** — and the two that called `InputString` **first** prompted the author for a tag and then discarded it. The dialog was written for "no cell selected" and, being unreachable, was never even seen to work. The fix is one `PackageScope` guard in `Referencing.wl`, `withInputNotebook`, which resolves `InputNotebook[]` once and shows `MessageDialog["Open a notebook first!"]` when there is none; each entry point now takes the notebook as an argument — `CopyCellReference[nb]`, `TagSelectedCell[nb]`/`[nb, tag]`, `InsertCitation[nb]`/`[nb, tag]`, `InsertEnvironment[nb, style]`, `LabelReferences[nb]`, `writeEnvironmentCell[nb, cell]` — and the argumentless form does nothing but call through the guard, which is the repo's own "pure cores with thin wrappers" convention finally applied here. The two-argument forms exist because a notebook alone still reaches `InputString`, so it is the *tag* that makes those two testable. `GoBack[]` is **not** this defect — see the next bullet for its own. Same silent-no-op signature as an undeclared cross-file helper, reached from an ordinary UI state.
- **`GoBack[]`'s hole is the same shape from the other cause: the *unset* `$LastHyperlinkCell` (`BasicFunctionality` T3), and a `CellObject` pattern alone does not close it.** Nothing assigns the symbol until a hyperlink is actually clicked — the state the palette's "Go back" is in the moment a paper is opened — so `SelectionMove[ $LastHyperlinkCell, All, Cell ]` stayed **unevaluated with zero messages**, measured against the installed 0.1.13. The second state needs its own word and its own detector: `SelectionMove` on a `CellObject` whose cell has been **deleted, or whose notebook has been closed, answers `Null` and does nothing**, silently, so the guard is `cell_CellObject` *plus* a liveness test — a deleted cell is recognised by `ParentNotebook[ cell ] === $Failed` (`CurrentValue[ cell, CellStyle ]` answers `$Failed` too), where a live one answers its notebook. The two dialogs are `"Follow a hyperlink first!"` and `"The cell that link was followed from is gone!"`. `GoBack` needs no notebook argument — it reads a global, not `InputNotebook[]`, so unlike the five it was always drivable headless, which is why the unset state must be measured **before** anything in `FrontEnd.wlt` assigns the symbol (the measurement records `ValueQ` alongside, so a polluted kernel fails a test instead of passing the right one for the wrong reason). What the guard does **not** fix: the stylesheets' own `ButtonFunction` writes `$LastHyperlinkCell = First[ SelectedCells[] ]` with no guard, so a click made with nothing selected stores an unevaluated `First[{}]` — the guard reports that honestly as "follow a hyperlink first", but the record is written wrong at the source, in all six sheets, and a click cannot be driven headless.
- **Window focus is not assertable in a headless front end, so nothing that depends on it can be fixed under this repo's bite rule.** `SetSelectedNotebook[nb]` leaves `SelectedNotebook[] === nb` **False** (as it leaves `InputNotebook[]` at `$Failed`), so "the right window came forward" has no measurement. That is why `GoBack` moves the selection and does *not* raise the parent notebook: a hyperlink followed with `"OpenInNewWindow"` leaves the author's selection changing in a window that is not in front, `SetSelectedNotebook @ ParentNotebook[ cell ]` is the one-call fix, and it would ship untested.
- **A headless `UsingFrontEnd` has no input notebook, so it reproduces "no document open" for free — which is the whole reason the guard is assertable.** `InputNotebook[]` is `$Failed` there and `SetSelectedNotebook` does not change it, and that is why no test in the repo had ever called `InsertEnvironment`, `CopyCellReference`, `TagSelectedCell`, `InsertCitation` or `writeEnvironmentCell` before T2 — `Referencing.wlt` reaches only the private helpers (`citationButton`, `labelReferenceCells`, `referenceDingbat`, `referenceButton`, `citationTargetStyle`). Two measured facts make the assertion possible: `MessageDialog` in a headless front end returns its `NotebookObject` **promptly** rather than blocking, so the dialog's own text reads back as `FirstCase[ NotebookGet[ dialog ], s_String /; StringEndsQ[ s, "!" ], None, Infinity ]` and the dialog can then be closed — the text, not the return head, is what the test asserts, since a *successful* call can also answer a `NotebookObject`; and `InputString` answers `$Failed` immediately with `InputString::ninit`, so a call that slips through to a prompt fails rather than hangs (`TimeConstrained` around each is still cheap insurance). The measurement that needs "no document" must be **first** in `FrontEnd.wlt`'s one `$measured` association: a notebook left open by any earlier measurement becomes the input notebook and the state under test is gone. Driven with a real notebook every overload is correct — the Theorem counter reads 1, 2, 3 across two theorems and a lemma with `Proof` and `DisplayFormulaNumbered` correctly not incrementing, and `ClipboardNotebook[]` reads back the one button `CopyCellReference` put there. `Block[ { InputNotebook = ( nb & ) }, … ]` after `Unprotect` was the T1 probe and is no longer needed for these.
- **Seven more entry points still carry that same `$Failed` hole, and it is one line each now that `withInputNotebook` is `PackageScope`.** `SetDocumentFontSize`, `SetMathFontSize`, `ResetDocumentView` (`View.wl`), `ConvertLaTeXCells`, `ConvertMathCells` (`Conversion.wl`), `ConvertToMaTeX`, `ConvertFromMaTeX` (`MaTeX.wl`) each hand `InputNotebook[]` straight to a `notebook_NotebookObject` overload — or to `convertCells[ …, notebook_NotebookObject ]` — so with no document open every one of them returns unevaluated with no message, exactly as the referencing five did. The palette's own stored code is unguarded the same way (the stylesheet menu, the two view sliders and the two export buttons all write `InputNotebook[]` bare), which is what `BasicFunctionality` T4 drives.
- **A style census of a live notebook must read `Cells[nb]`, not pattern-match the `Notebook` expression** — two ways, in opposite directions, and both look like a broken writer. `StyleDefinitions -> Get[sheet]` **embeds** the sheet, so `Cases[ NotebookGet[nb], Cell[_, s_String, ___], Infinity ]` walks 81 stylesheet cells and reports styles the document does not have; restricting the levelspec to `{1, 2}` then reports `{ }`, because writing cells **groups** them into `CellGroupData` and pushes them deeper — the grouping trap met without a reopen. Use `First @ Flatten @ { CurrentValue[ #, CellStyle ] } & /@ Cells[ nb ]`.
- **A resolved-style read cannot answer "what face does this run render in", and for the character styles the two answers differ** (`ImportDisplayDefects` T5). `CurrentValue[nb, {StyleDefinitions, "Citation", FontFamily}]` answers **Times 12** under every one of the seven sheets — against prose of Palatino 13, Latin Modern 13, Times New Roman 13, Times 14 and Source Sans Pro 15 — because `Citation` → `Hyperlink` → `Link` and `Link` comes from front-end resources outside any sheet. That reads exactly like a defect and is not one: **rendered**, a `Citation` run inside a `Text` cell measures 406 ink at height 15 where plain prose is 409/15 and a deliberate Times 12 run is 365/12, so the run takes the *cell's* face and only the abstract chain says otherwise. Dropping the `Link` parent and setting `FontFamily -> Inherited` both change nothing, for the same reason. Cost: this nearly rewrote seven stylesheets for nothing. Same family as reading a print size off the bare style path, and the reason any face claim needs `inkArea`.
- **`NotebookWrite` at a cell-bracket selection *replaces the cell*, and there are four selection states, not one.** Insertion point, contents selected, nothing selected, cell selected by its bracket — `InsertCitation` had only ever been driven in the third. In the fourth it destroyed the cell's content and left `Cell[BoxData[button], "Text"]`, which measures **482 ink at height 17** and 113 px wide because a `BoxData` cell does not wrap: `BoxData` renders in the box face whatever the cell's style says, so the silent data loss and a reference in the wrong font were **one** bug (Pavel's screenshot). `citationInsertionPoint` recognises a whole-cell selection by `NotebookRead` answering a `Cell` and moves inside the contents; a cursor already in contents reads as `""` with the cell still in `SelectedCells`, so it is left alone; no selected cell at all means an empty `Text` cell is made rather than letting the front end invent a `BoxData` one. The contents-selected case is pinned as *still overwriting*, because that is what every editor does.
- **A `CellDingbat` cannot read the options of the cell it labels.** `CellDingbat -> Cell[BoxData[ToBoxes @ Dynamic[... CurrentValue[EvaluationCell[], CellTags] ...]]]` renders, and renders empty: inside the dingbat `EvaluationCell[]` does not resolve to the owning cell. A label that depends on the cell's own tags has to be written into the cell (`referenceDingbat` in `Referencing.wl`), not derived at display time. Counters are the exception — `CounterBox` is a front-end box and works in a dingbat, which is how the theorem environments number themselves.
- **`CounterBox[counter, tag]` resolves the counter at the cell tagged `tag`, not at the box's own position** — the front end's native cross-reference, needing no kernel, correct in the PDF, and renumbering itself when cells move. It is what a citation to a numbered environment is built from (`citationButton[tag, style]` in `Referencing.wl`). An unknown tag renders `XXX`, so the *style* is resolved at insert time and a tag no cell carries falls back to `[tag]`. **`CopyCellReference` now shares it, and the old note that it could not is wrong in a way that was hiding a second defect** (`FirstReadingDefects` T4): a `CellID` was never a workable key here at all — see the next bullet — so the copy path tags the target instead and both renderings collapse into `citationSpecButton[tag, spec]`.
- **An imported cell has no `CellID`, and a `CellID` of 0 is not "no cell" but *every* cell.** `CurrentValue[cell, CellID]` reads **0** on any cell the importer built, and `Cells[nb, CellID -> 0]` answers the whole document — so `First[Cells[CellID -> 0], $Failed]` is the document's **first** cell, where a paper's `Section` counter is 0 and its `Theorem` counter is 0. That is the whole of Pavel's reported `Theorem 0.0`: not one wrong lookup but two independent defects wearing one string, the other being the style-spec read below. `NotebookFind[nb, 0, All, CellID]` likewise navigates nowhere, so the pasted reference was also dead. And a `CellID` **cannot be repaired onto an existing cell** — measured, `SetOptions[cell, CellID -> n]` and `CurrentValue[cell, CellID] = n` are both silent no-ops and the cell's option list stays empty, while a cell *created* with one keeps it. So anything that must resolve at a cell keys on a **tag**: `CopyCellReference` takes the cell's first tag and, for an untagged cell, generates the first unused `ref:n` and writes it (Pavel's call, 2026-07-29 — auto-tag rather than prompt or refuse, and the tag is what makes the reference exist in the exported `.tex` too).
- **What a copied or referenced number prints comes off the target *cell*, and there are three cases where the `\ref` fix named two.** A cell carrying **no** dingbat takes its style's spec (the common case — the sheets number the twelve environments); a cell whose dingbat carries `CounterBox`es takes the word *and* the chain out of it (an imported `axiom` is style `Theorem` with a per-cell `Axiom S.SS.TheoremAxiom.`, which is why the style lookup printed the wrong word over counters the cell never increments); and a cell whose dingbat carries **none** is unnumbered — a starred environment, a bibliography entry — so there is no number to print and the reference must read `[tag]` rather than falling back to a spec whose counters that cell deliberately suppresses. A `CellDingbat -> None` continuation cell reads as the first case, which is right: the number belongs to the cell heading the group and resolves to the same value there. The label's trailing period is a terminator and is dropped from the suffix; an equation's closing parenthesis is not.
- **`NotebookPut[expr, nb]` does not update a notebook, it replaces every cell in it — so a whole-notebook rewrite is not merely slow, it invalidates every reference into the document.** Measured on the causal paper: after one `LabelReferences` of the old shape, **174 of 174** held `CellObject`s answer `$Failed` from `ParentNotebook` and all 174 carry *fresh* `CellID`s, and `SelectionMove` on one of the dead ones answers `Null` and does nothing — `GoBack`'s stale-cell state reached with nothing having been deleted, which is the reported "clicking references after a refresh misbehaves" (`FirstReadingDefects` T6). The cost side is as blunt: to change 14 dingbats it hands the front end **22,078,272 bytes over 486 cells, 7 of them rasters**, where the per-cell route hands over **4,616 bytes over 14 cells** — kernel-side 0.177 s then 0.076 s steady against 0.0029 then 0.0014 s. So a control that touches a known style writes those cells (`Cells[nb, CellStyle -> …]` + `SetOptions`) and never the notebook. The freeze *itself* has **no headless measurement**: a `Visible -> True` notebook in the service front end times identically to an invisible one (0.075 against 0.075), so the wall clock on a real window is in the same unmeasurable class as window focus, and what is assertable is liveness — which is the better test anyway, being neither flaky nor a property of this machine.
- **`SetOptions[cell, option -> Inherited]` *removes* the option from the cell rather than storing the word.** Measured: a cell given a `CellDingbat` and a `ParagraphIndent` and then set to `Inherited` reads `Options[cell] === { }`, and the notebook expression shows a bare `Cell[…, "Reference"]`. That is what lets a per-cell route and an expression route that *deletes* the option leave byte-identical cells, and it is why clearing a stale label needs no separate mechanism. `CurrentValue[cell, option] = Inherited` does the same.
- **A reference on the clipboard has to be a `Cell[TextData[…]]`, and the shape is a measurement rather than a preference.** Pasted into prose, a `Cell[BoxData[button]]` payload renders in the **box face** — 29 px tall against the prose's 19 — which is the same wrong-font defect as `InsertCitation`'s overwrite, and a bare `ButtonBox` on the clipboard pastes as **its own boxes spelled out as text**. The `TextData` form is the prose face (height 19, ink 1143 against the control's 386). It splits on the way through — the clipboard alone cuts a two-counter button into 4 fragments and the paste cuts a three-counter one into 6 — which is the reopen-split shape `mergedButtons` already rejoins: every fragment carries the same `ButtonData`, so each navigates and the export still emits one `\ref`. **So a button count is the wrong assertion**: it measures the splitter, not the copy. Assert the distinct `ButtonData` keys and that each resolves to the copied cell.
- **`Rasterize` on a single cell strips document context**: every `CounterBox` in it reads 0 and every tagged one reads `XXX`. To see a counter, render the whole notebook — `Export[file, notebookObject]`.
- `NotebookWrite` of a whole `Cell[TextData[...]]` splits a `ButtonBox[RowBox[...]]` into one button per run; writing the bare `ButtonBox` at a selection point leaves it intact. Both render the same, but only the inline form round-trips.

## Palette state and folding

- Palette state persists **despite `Saveable -> False`**: the front end saves a palette's own `TaggingRules` in `$UserBaseDirectory/FrontEnd/init.m` under `CurrentValue[$FrontEnd, PalettesMenuSettings]`, keyed by palette file name. Write state on `EvaluationNotebook[]` under a flat key, as the built-in palettes do; do not use `$FrontEnd` tagging rules.
- `CurrentValue[EvaluationNotebook[], {TaggingRules, key}, True]` is fully front-end-side — no kernel is launched to display or fold the palette. Set it from an `EventHandler` with `Method -> "Preemptive"`, and use two handlers (set `True` / set `False`) rather than a `Not`.
- `PaneSelector` reserves the size of its **largest** pane unless given `ImageSize -> Automatic` explicitly. Without that option a collapsed group still occupies its open height and the fold does nothing.
- `Rasterize` renders `Dynamic` as a placeholder and `PaneSelectorBox` at max size, so a raster can neither show nor measure fold state. Build a separate static rendition for screenshots (`Scripts/BuildPalette.wls` has `staticGroup` beside `paletteGroup`).
- Never `Import` **or `Get`** a palette `.nb` into a variable to inspect it — the result is re-evaluated, so a literal `EvaluationNotebook[]` becomes `$Failed` and every `CurrentValue` collapses to its default, reporting one window size for every fold state. Read it as text, or measure via `AbsoluteCurrentValue[nb, WindowSize]` after `NotebookOpen`.
- **A palette button's code is stored verbatim, so it cannot call a helper defined in the build script.** `kernelButton` is `HoldRest`, so `kernelButton["Import .tex file…", importDocument[]]` writes *the call* into the `.nb`, and at click time the front end's kernel has no `importDocument` — the button silently does nothing, the same failure as an undeclared cross-file helper. Everything a button does has to be written out literally, in `System`` symbols plus fully qualified paclet ones. That is why the Import and Export buttons carry their own `SystemDialogInput` inline rather than calling a wrapper (`ConversionUX` T1).
- **The palette can be asserted as text, and that is the only safe way to read it back at all** — `Get`/`Import` as an expression re-evaluates it, per the note above. Undo two things first: the exporter wraps long lines with a trailing `\` and a newline, and it escapes each box string as `\<\"…\"\>`. `StringDelete[source, {"\\\n", "\\<", "\\>", "\\\""}]` leaves `ButtonBox["Typeset"` and the tooltip sentences plainly matchable, which is how `Tests/Palette.wlt` pins the labels, the group headings and the six tooltips of a generated artifact. A named character in a label survives as its **own escape**, so a test for `Import .tex file…` must spell `\\[Ellipsis]` and not the character.
- To measure a fold state, patch the palette's **existing** `TaggingRules` option as text — the generated file already carries one (an all-`True` association the exporting front end writes), a second copy of the option is ignored, and the association spans several lines, so the regex needs `(?s)`: WL's `RegularExpression` `.` does not cross a newline.

## Style overrides on a document

`View.wl` ships **two** controls, both font sizes: `SetDocumentFontSize` and `SetMathFontSize`, cleared by `ResetDocumentView`. A third, `SetContentWidth`, shipped in 0.1.5–0.1.7 and was **withdrawn in 0.1.8** at Pavel's call — a content column is not wanted in any form, relative or absolute. The cell-margin and paper-geometry notes below are kept because they were expensive to establish and they describe the front end, not that control; do not read them as describing shipped code. `ResetDocumentView` still clears the old `"ContentWidth"` tagging rule so documents written with those versions are left clean.

- **The two controls are not independent, and that asymmetry is the model** (Pavel's call, 2026-07-29; `FirstReadingDefects` T5). `mathViewScale` falls back to `documentViewScale` rather than to 1, so an untouched math slider means "scale with the page" and one slider moves prose, display mathematics, inline mathematics and MaTeX coherently; an explicit math size overrides it and is measured against the mathematics anchor instead. Independence was the reported defect: an author who enlarged the prose watched the equations stand still, which reads as mathematics having been left behind rather than as a second control waiting to be found. Two consequences. `SetDocumentFontSize` must call `rescaleMaTeXCells` — a MaTeX cell is an image and inherits nothing, and before the model changed that call could not affect one. And **`Automatic` and a scale of exactly 1 are different states**: `fontSizeCells` writes nothing for the first and writes every style at its own base size for the second (an author dragging the slider back to the sheet's own size), which looks identical on the page and is what makes the four slider states measurable at all — see the width note below.
- **A *relative* `FontSize` on `InlineFormula` renders at the SQUARE of the ratio.** Measured: swept `r` over `{0.5, 1, 1.05, 1.5, 2}` against hosts 13, 26 and 52 and read the **width** of `x + y` — the island comes out at `r² × host` every time, so `r = 2` on a host of 26 draws 104 pt and not 52. The style is resolved once for the inline `Cell` and again for its own contents, and `Inherited` picks the ratio up both times; an *absolute* `FontSize` on the same style is exactly linear (13/26/39/52 → widths 26/51/77/103), which is what rules out a mis-measurement. So the sheet's own `1.05` draws an island at **1.1025 ×** its host, and the shipped math control was worse than Pavel reported — at twice the anchor it wrote `2.1` and drew 4.41 × the host, not 2.1 ×. The ratio to write is therefore the square **root** of the wanted scale: `$inlineMathRatio Sqrt[mathScale/docScale]`, the quotient being the separate fix for the double-scaling (the host already carries the document ratio).
- **Width is a size measurement where ink and height are not.** A display formula's exported width is exactly linear in its size — `x + y` is 26, 51, 77 and 103 px at 13, 26, 39 and 52 pt — so comparing two sizes needs no tolerance. Ink grows about as `size^1.5`, so an ink comparison across two sizes needs one nobody can justify; and **height is floored by the enclosing text cell's line height**, which is exactly how the squared ratio stayed hidden — `r = 0.5` on a host of 26 is a 6.5 pt island sitting in a 14 px line, so a height sweep reads the floor and reports linearity.
- **A state that leaves `Text` unwritten cannot be measured headless at all.** An island's size is its host cell's size times a ratio, and under an installed private sheet the parent is an embedded notebook, so any style the sheet does not itself write falls through to `Default.nb` (`Text` 15) — the math-only state therefore renders an island against the wrong host and is unmeasurable, though it is correct in the product where the parent is a named sheet. Two further facts make the four-state measurement work: with **no** override installed the export does not crop horizontally (729 px, the window), so a width reading needs a private sheet present; and dragging the text slider to the sheet's own size gives a base state that writes every style at its base size, which is comparable with the rest.

- The `"Printout"` variant of a style wins over the bare style name **across the whole stylesheet chain**. Since `LaTeXBase` sets an explicit `FontSize` on every prose/math style's `"Printout"` variant, an override written only on the bare name changes the screen and leaves the PDF byte-identical. Always write both.
- `CurrentValue[nb, {StyleDefinitions, style, option}] = value` is silently ignored. Build the private sheet (`Notebook[{Cell[StyleData[StyleDefinitions -> parent]], overrides...}, StyleDefinitions -> "PrivateStylesheetFormatting.nb"]`) and install it with `SetOptions`.
- **Reading** that same path *does* work, and resolves through the whole chain — including styles no MathNotebook sheet declares (the `Item` family, which comes from `Default.nb`) and a document still on `Default.nb`. It is the way to get a style's base geometry; read it off a scratch notebook created with the *parent* sheet, or a second call compounds its own override.
- To read the **print** value, put the environment in the path as a list: `CurrentValue[nb, {StyleDefinitions, {"Theorem", "Printout"}, FontSize}]` returns 10 where the bare path returns 13. `StyleData[style, "Printout"]` in that position does **not** work — it silently returns the screen value, so every printout override gets written at its screen size. Filter the results for `NumericQ`: `Default.nb` resolves `DisplayFormulaEquationNumber` to the symbolic `-1 + Inherited`.
- Read the *list* of styles to touch from `LaTeXBase.nb`, not from the chain. The chain happily resolves a size for the character styles (`Hyperlink`, `Citation`, `URL`) too, and pinning those stops an inline citation from inheriting the size of the cell it sits in.
- **`Scaled` in `CellMargins` always resolves against the window, in print as much as on screen** — never against the paper. Measured: a bare `Scaled[0.2]` in the `"Printout"` variant put the left ink at 174 on *both* 612 pt and 842 pt paper. So on screen `Scaled[0.5] - width/2` on both sides is exactly an absolute centered column that tracks a window resize, and in print the same expression is meaningless. Earlier sessions recorded both halves of this wrongly (T4 read a `Scaled` print inset as tracking the printable width, T6 read the sum form as the broken case); the sum is fine, the environment is what differs.
- **A printout cell margin is laid out at 0.72 and only then put on the paper.** `Default.nb` gives `Cell[StyleData[All, "Printout"]]` a `Magnification -> 0.72`, so a printed margin is `0.72 ×` its value, measured in from that edge's `PrintingMargins`. An absolute column of `w` points on paper is therefore the point margin `(printable - w) / (2 × 0.72)` — verified to the point at 200, 300 and 400 pt on two papers. Reading the 0.72: `AbsoluteCurrentValue[nb, Magnification]` on a scratch document created with `ScreenStyleEnvironment -> "Printout"`. The obvious path, `CurrentValue[nb, {StyleDefinitions, {style, "Printout"}, Magnification}]`, silently answers 1.
- Printable width is `First @ CurrentValue[nb, {PrintingOptions, "PaperSize"}] - Total @ First @ CurrentValue[nb, {PrintingOptions, "PrintingMargins"}]`; the template sheets declare A4 with 72 pt margins, so it is 451.28.
- `PageWidth -> w` in a style *is* absolute (identical ink `{102, 252}` on both papers) but left-aligns at the style's own margin, and combining it with symmetric `Scaled` margins fights — `Scaled` then resolves against the style's own `PageWidth`, and the two together collapsed the block to 73 pt and were not centered.
- Measuring an exported PDF: run the page headers and footers off (`PageHeaders`/`PageFooters -> {{None, None, None}, ...}`) or their own margins widen the ink column, and trust only the **left** ink edge — prose is ragged right, so the right edge lands wherever the longest line happens to end.
- Headless verification trap: a private sheet whose parent is an **embedded** notebook (`Cell[StyleData[StyleDefinitions -> Get[path]]]`) applies your own override cells but lets every *unoverridden* style fall through to `Default.nb` instead of the intended parent. Styles you wrote read correctly while styles you did not read Default's values, which looks exactly like a leaking control. Only the document-level `StyleDefinitions -> Get[path]` form resolves properly.
- That trap reaches **notebook options too, not just styles**: with an embedded parent, `CurrentValue[nb, {PrintingOptions, "PaperSize"}]` answers `Automatic`, so anything computed from the paper becomes symbolic and the printed result is silently garbage. It also means a headless PDF export uses `Default.nb`'s 54 pt printing margins while a read taken before the wrap reports the sheet's own 72 — the two disagree by exactly the amount that makes an absolute column look wrong. Read paper geometry only off the **bare parent**: restore `StyleDefinitions -> parent` first, read, then install the private sheet.
- **Never stage a stylesheet into `$UserBaseDirectory/SystemFiles/FrontEnd/StyleSheets/`** to make a sheet resolve by name in a script. It does resolve — and then *every* subsequent front end launch on the machine hangs indefinitely, including unrelated builds, until the directory is removed. Cost two wedged sessions and a round of killed kernels to find. Embed the sheet instead and accept the trap above.
- A style declared `StyleData[name, StyleDefinitions -> StyleData["Text"]]` — the theorem environments, `Proof`, `Reference`, `Author`, `Date` — does **not** pick up a child sheet's override of `Text`; the inheritance is resolved inside the parent. Such a style carries no bare `FontSize` of its own, so an override generated from the base sheet's declared sizes skips it and its size never changes on screen.
- `CellMargins` accepts `Scaled[fraction] + points`, and the front end resolves the sum (`Scaled[a] + Scaled[b]` behaves as `Scaled[a + b]`). A symmetric `Scaled[0.5] - width/2` is therefore an absolute on-screen column, and a per-style point offset added to it keeps each style's own indent — section numbers and theorem dingbats are drawn to the left of their own cell margin. Anchor such offsets on `Text` so the *body* ends up centered; anchoring on the smallest margin centers the hull and leaves the body visibly off-centre (measured 11.5 pt on a 340 pt column). The offsets are then negative, so a printed inset has to be clamped at the widest hang or a section number falls off the paper.
- Of two `StyleData` cells for the same name and environment in one sheet, the **first wins and the second is discarded whole** — its options are not merged in, so an option written only in the second never applies and silently falls back to the parent (measured both for the same option twice and for two different options). Emit exactly one cell per style and environment, carrying every option; never append a second. This is why `View.wl` runs its generated cells through `mergedStyleCells`, and it is the trap that made the withdrawn width control a silent no-op on every style that also carried a size.
- The front end **drops `TaggingRules` from a private stylesheet notebook** — string, rule list or association alike — while adding `Visible` and `FrontEndVersion` of its own. To recognise a sheet you generated, mark it with a hidden cell (`Cell[StyleData["<marker>"], StyleMenuListing -> None, MenuSortingValue -> None]`); cells survive the round trip. Without a marker each install nests the previous sheet inside the new one and reset can no longer recover the real parent.
- Reset = recover the parent with `FirstCase[..., Cell[StyleData[StyleDefinitions -> name_]] :> name]` and assign it back verbatim — it is a string from the menus but a `FrontEnd`FileName` from the palette.
- `Magnification` never reaches print; it is not a font-size control.
- Headless testing: `"MathNotebook/AMSArticle.nb"` and `FrontEnd`FileName[...]` have both been seen to fall back to `Default.nb` silently in a `wolframscript` run with the paclet installed. What always works is embedding the sheet: `StyleDefinitions -> Get[<absolute path to AMSArticle.nb>]`. Assert the sheet loaded (`CurrentValue[nb, {StyleDefinitions, "Title", FontSize}]` is 26, not 45) before trusting any measurement — that assertion is the point, not the resolution method.
- **The LaTeX↔MaTeX pair carries a *second* TeX string on the cell, and the two must not be merged.** `"SourceTeX"` is the body MaTeX is handed and every later re-render is given — so it cannot wear delimiters, or `SetMathFontSize` feeds `$$…$$` to LaTeX — while `"LaTeXSource"` is what the author typed, delimiters, spacing and all, and is what `ConvertMaTeXToLaTeX` gives back. `resizedMaTeXCell` therefore has to pass the source through `maTeXCell`'s fifth argument or dragging either slider silently costs a converted cell its round trip, which no kernel test sees (the cell still renders, still exports, still round-trips through `SourceTeX`) — the assertion is `FrontEnd.wlt`'s `TypedBack`, and the bite is dropping the key, which fails that test and **only** that test. Both directions parse through one `displaySource`, which `mathTeX` now calls too: the body inside the delimiters where a cell's text has any, the whole of it where it has none, an `align` becoming an `aligned`. And **`ConvertLaTeXToMaTeX` is the one conversion whose empty selection is not "the whole notebook"** — every other transform is keyed on a math style and leaves prose alone, where this one reads a cell's own text and would render every paragraph in the paper as an image, so it takes `convertSelectedCells` and refuses.
- **MaTeX comes in two forms since 0.1.24 — a display cell and an inline island — and one predicate covers both.** `inlineMaTeXCell` is the island's single builder (`"DisplayStyle" -> False`, style `"InlineFormula"`, the same `SourceTeX`/`MaTeX` tagging as `maTeXCell`), so `maTeXCellQ`, `rescaleMaTeXCells` (which now selects by `maTeXContentQ`, cell or island) and the trip back to LaTeX treat both through one shape. `ConvertToMaTeX` converts a prose cell island by island, skipping anything holding a `ButtonBox` so citations survive; `ConvertLaTeXToMaTeX` branches on `mixedLaTeXQ` — one display formula or a bare fragment renders whole as before, prose renders piecewise, display spans to display cells and `$…$`/`\(…\)` runs to islands; the reverse conversions re-wear the dollars (`\(…\)` comes back as `$…$`, the one paraphrase). The `$displayDelimiters` fourth field is now the math-mode INNER environment or `None` — `align`/`gather`/`multline`/`alignat`/`flalign`, starred or not, mapping to `aligned`/`gathered`/`multlined`/`alignedat` — and the closing brace of each opener is what keeps `\begin{align}` off the head of `\begin{alignat}`. `multlined` lives in mathtools, which MaTeX's `BasePreamble` lacks, so every rendering entry point calls `ensureMaTeX[]` — `Needs` plus appending `\usepackage{mathtools}` to the user `"Preamble"` once and only when absent. Cross-file kernel symbols MUST be `PackageScope`d or each file gets its own `PackagePrivate` copy silently (that bit `$displayDelimiters` first), and a bare repeated name is not a string-pattern backreference — capture twice and compare under `/;`.
- **A MaTeX cell is an image, so its size is neither inherited nor recoverable from the cell — it has to be told, and there is exactly one place that builds one.** `maTeXFontSize` scales `$maTeXBaseFontSize` by the ratio the math control is holding (`Round[14 × MathFontSize / anchor]`, so an untouched document gives back 14 exactly); `SetMathFontSize` re-renders through it *and* `ConvertToMaTeX` converts through it, or a newly converted cell sits at 14 until the slider is next touched. That was a real bug for five releases, and the cause was two independent constructions of the same cell — `toMaTeXCell` and `resizedMaTeXCell` — that happened to differ on the size, so the repair is the single `maTeXCell[tex, style, options, size]` both now call rather than a corrected literal. `ConvertToMaTeX[{cell, ...}]` is the one overload with no notebook of its own and gets it from `ParentNotebook @ First[cells]`. `maTeXFontSize` has a pure `maTeXFontSize[parent, settings]` core so the arithmetic is assertable kernel-only; the wiring is not, and is measured in `Tests/FrontEnd.wlt` as the **width of the rendered `GraphicsBox`** under an untouched document against one at twice the anchor. MaTeX renders fine in a bare `wolframscript` kernel — no front end needed — but reads its `pdfLaTeX`/`Ghostscript` paths from persistent config, so on a machine where `InstallMaTeX[]` has never run the call stays unevaluated and every width or ink measurement quietly reads 0; the test writes that configuration itself and is guarded on the paclet and both executables being present, emitting no tests rather than failing ones when they are not.
- **A MaTeX cell is no longer a bare picture: the graphics ride in the front end's own TeX assistant box, which is what makes the mathematics editable again** (`EditableMaTeX` T1, Pavel's report and call, 2026-08-01). `maTeXBox` writes `TemplateBox[ <| "boxes" -> graphics, "errors" -> { }, "input" -> tex, "state" -> "Boxes" |>, "TeXAssistantTemplate" ]` — the box Ctrl+4 makes, whose `DisplayFunction` (`Core.nb`) is `InputAssistant`InputAssistantBoxes[ 1, "TeXAssistant", … ]` and whose `InterpretationFunction` is `Slot["boxes"]`. Four measurements. The wrapper is **display-transparent**: one `DisplayFormula` rendered as a whole notebook at 144 dpi under `Background -> White` + `LightDark -> "Light"` measures **{183, 40} px and 1083 ink** bare and identically wrapped. It **survives a file**: `Export` then `NotebookOpen`/`NotebookGet` gives back the cell with all four slots and the input string byte-intact — unlike a `ButtonBox` in a `TextData`, this box is not split by the reopen, and `Tests/FrontEnd.wlt` asserts the same of a `NotebookWrite` (`"Editable"`/`"EditableTeX"`). Only **`"Boxes"`** may be written: a kernel-written `"state" -> "Input"` falls through `InputAssistantBoxes`' own `Which` to `pleaseUpgradeBoxes` and draws *"Displaying this output requires a more recent version"*, which reads as a version fault and is not one. And an **edit re-renders through `InputAssistant`TeXStringToBoxes`** — the symbol `$maTeXPreferences` overrides — so it comes back as MaTeX exactly when `$useMaTeXQ` is set and as native boxes otherwise; the paclet ships that hook with `$useMaTeXQ = False`, which is why T2 exists.
- **The box's `"input"` slot outranks the `"SourceTeX"` rule, and an edit invalidates `"LaTeXSource"`.** Pavel's call: TeX edited in the notebook must reach the `.tex` — the `thebibliography` side of the who-owns-the-entries split rather than the `.bib` side. The precedence is stated **once**, in `storedSourceTeX`, so every reader inherits it (`displayTeXString`, `inlinePartToTeX`, `mathTeX`, `laTeXSourceText`, `resizedMaTeXCell`); `maTeXEditedQ` is box-differs-from-rule, and `storedLaTeXSource` answers `$Failed` when it holds, because the recorded typed source describes the formula *before* the edit and handing it back would discard the edit silently. Both halves bite (`Tests/MaTeX.wlt`, measured): dropping the precedence fails **3** tests, keeping the stale typed source fails **1** — and that one's actual output is the pre-edit `$$ x^2 $$`, which is the loss itself. A side effect worth knowing: a cell the author made with **Ctrl+4 alone** carries the box and no tagging rule, and now exports its TeX too. `maTeXBoxTeX` is deliberately narrow — the box as a cell's whole content, or the box itself, never a `FirstCase` at `Infinity` — because a `Text` cell may hold several inline assistant boxes and "the TeX of this cell" is then not a question with one answer.
- That fallback is **not** unconditional, and the earlier note that the service front end never sees a freshly installed paclet's `FrontEnd` extension is wrong. Measured with no MathNotebook installed at all, `FrontEnd`FileName[{"MathNotebook"}, "AMSArticle.nb"]` gives Title 45; after `PacletInstall` from the cloud plus ``FrontEndExecute[FrontEnd`ResetMenusPacket[{Automatic, Automatic}]]`` **in the same `UsingFrontEnd` session** it gives 26, as does a front end launched after the install. So the menu reset really does make new stylesheets live, and a stale read means stale paclet data, not an incapable service front end.
- **That last claim does not reproduce for a locally installed paclet, so treat by-name resolution as unmeasurable here rather than as working (`BasicFunctionality` T4).** Measured against an installed 0.1.16 built from the working tree: `FrontEnd`FileName[{"MathNotebook"}, sheet, CharacterEncoding -> "UTF-8"]` and the string form `"MathNotebook/AMSArticle.nb"` both give Title **45** where the embedded `Get` of the same file gives 26 — for all **six** sheets, before a reset, after `ResetMenusPacket` **in the same session**, and with the service front end **killed and freshly launched** (verified none was running). The two measurements differ only in that the working one installed from the cloud, which is not a difference any resolution path should see. What follows for testing is unchanged — embed the sheet with `Get` and assert it loaded — but the consequence for the *product* is that the palette's own "Apply stylesheet" menu and `ImportLaTeXDocument`'s sheet choice, both of which set the sheet **by name**, cannot be verified in this environment at all. That is Pavel's to confirm by clicking, and it is the one T4 item left open.

## Publishing

- `Scripts/PublishPaclet.wls` owns publishing: it stages `PacletInfo.wl` + `Kernel/` + `FrontEnd/` + `Assets/` + `Tests/` + `Documentation/` (each only if present), archives, uploads to `MathNotebook.paclet`, and only then writes the version marker `MathNotebook-version.txt` — archive first, so a failed upload never leaves the marker promising a version that is not there. It is still the canonical publisher because of that ordering and the version marker; the generic `publish-paclet`/`build-paclet` recipe no longer drops the palette and stylesheets (it stages every top-level item as of plugin 4.2.0) but it knows nothing about the marker.
- **The reference pages ship *inside* the paclet and are deployed nowhere else — that is Pavel's call, 2026-07-28, and it is a rule and not an accident.** `PacletInfo.wl` declares `{Documentation, Root -> Documentation, Language -> English}` and `PublishPaclet.wls` stages the directory, so the 22 pages travel in the archive and resolve in the Documentation Center (F1) and in `?Symbol` once installed. A browser mirror of them — one cloud notebook per symbol under `MathNotebook/Documentation/ref/` plus an HTML index, produced by the plugin's `deploy_paclet_docs.wl` with the `paclet:` links rewritten to deployed siblings — **existed until 0.1.14 and was deleted**, along with the README link that pointed at it. Do not recreate it: a second copy of the pages on the cloud is a second thing to keep in sync, and it had already fallen behind in both ways that matter — 21 pages against the paclet's 22 (`ExportLaTeXBundle` shipped in 0.1.13 and was never mirrored) and every usage line one release stale. Regenerating a page is `Scripts/RegenerateUsage.wls`, not a deploy.
- **A 23rd reference page is cheapest as a transform of a sibling, not as a fresh skeleton.** `Get` the nearest existing page, replace the `ObjectName`/`Usage`/`Notes`/`SeeAlso`/examples/`Keywords` groups and the `Categorization` URI, and regenerate **every `CellID` and `ExpressionUUID`** — a page sharing either with its template is one the Documentation Center can resolve to the wrong one. Order matters: rewrite the template's own `ref/<oldsymbol>` self-references **first**, or the same pass rewrites the deliberate back-links to the old symbol that the new page's usage and See Also carry. Two details of the format: a `Usage` cell's separator between the `InlineFormula` and its prose is `" \[LineSeparator]"` (U+2028), and prose strings take markdown links (`[Name](paclet:…)`) directly.
- The cloud URLs live once, as `PackageScope` symbols in `Kernel/Update.wl`; the script reads them off the loaded paclet and aborts if they are not strings (a `PackageScope` symbol referenced from outside silently exists with no value — the trap in *Conventions*). `MATHNOTEBOOK_PACLET_URL` / `MATHNOTEBOOK_VERSION_URL` override both for a staging dry run.
- `$CloudBase` is `None` in `wolframscript`, so `CloudConnect[]` fails there with `invbase` — set it to `https://www.wolframcloud.com` first. The MCP kernel is already connected.
- `URLRead[request, {"StatusCode", "Body"}]` returns an **Association**, not a list; match it with `KeyValuePattern`. `"ContentLength"` is **not** an allowed element (`URLRead::noelem`, and the call returns the message text where a number was expected) — measure a cloud object with `Length @ r["BodyBytes"]`.
- **`Scripts/DeployPreviews.wls` is part of publishing, not an extra.** It deploys `Tutorial.nb`, which the README links *above* the install line, so a release that skips it leaves the first thing a reader opens as the previous tutorial. That is what nearly shipped in 0.1.11: the cloud copy still carried the T1 scratchpad filler and described neither `PlainArticle` nor the importer.
- **The public context holds 28 symbols where `PacletInfo.wl` declares 27** as of 0.1.23 (`ConvertLaTeXToMaTeX`/`ConvertMaTeXToLaTeX` are the newest; it was 26/25 at 0.1.22, 25/24 at 0.1.21 and 23/22 when this was first written, and the gap is always the same one symbol). `$LastHyperlinkCell` has a usage string but no `Symbols` entry and so no autoload stub and no reference page; it is reachable only because the README tells people to `Needs` the paclet. Any count quoted from the declaration is not the API surface — read both, as `Complement` over the two. **`Names` returns the shortest unambiguous name**, so with the context on `$ContextPath` it answers short names and a `Complement` against the fully qualified declaration reports *every* symbol as undeclared — which is how this one-symbol gap first presented as a 22-symbol one.
- A cloud object read back **immediately** after `CloudExport` came back unreachable once and read correctly a minute later (the cloud serves `cache-control: public, max-age=60`). Do not treat a single failed read right after publishing as a broken marker. The same caching makes two reads of one marker seconds apart disagree — a probe must read once and bind, never call `cloudVersion` twice and compare.
- Versions compare only as padded integer lists (`PadRight[ToExpression @ StringSplit[v, "."], 4]`); as strings `"0.1.12"` sorts before `"0.1.9"`. `Order[a, b]` is `-1` when `a` sorts **after** `b`, so "the cloud is newer" is `Order[cloudList, installedList] === -1`.
- `UpdateMathNotebook[]` needs a front end — `Notebooks[]`, `MessageDialog` and `FrontEndExecute` all fail in a bare `wolframscript` kernel. They do **not** fail inside `UsingFrontEnd[...]`, so the whole install path *is* drivable headless: wrap `installUpdate` in `UsingFrontEnd`, having first `NotebookOpen`ed the palette `Visible -> False` so `reopenPalette` has something to close. Only the `MessageDialog` in the exported wrapper is left untested that way. Its decision core (`updateAction`, `updateMessage`) is pure and is what the `.wlt` tests cover.
- A file-private helper is reachable from a probe by its full name — `Symbol["WolframInstitute`MathNotebook`Update`PackagePrivate`installUpdate"]` — which is how the install path gets exercised without giving it a `PackageScope` it does not otherwise need.
- Run `Scripts/*.wls` with `wolframscript -file`, never `-code` + `Get`. Under `-code` the scripts' `$ScriptCommandLine` is non-empty but meaningless, so it matches their `{path_, ___}` branch, the `MATHNOTEBOOK_REPO` fallback never fires, and the repo root comes out as something like `/private` — `DeployPreviews.wls` then cheerfully published four samples with `$Failed` stylesheets. `DeployPreviews.wls` now sets `$CloudBase`/`CloudConnect[]` itself so `-file` is always enough.

- **The repair is to never assign a stylesheet *name* onto a document at all, and `applyViewSettings`'s old intermediate assignment was unnecessary as well as lethal** (`ResetViewRender` T2). It put the recovered parent back by name, unconditionally, before installing the new private sheet; nesting is already prevented by using the *recovered* parent as the new sheet's parent, so there is now **one** `SetOptions`, always of a private sheet, and a **reset installs a neutral sheet** — every style restated at its own base size, the "scale exactly 1" state § *Style overrides* already distinguishes from `Automatic` — rather than removing the sheet.
